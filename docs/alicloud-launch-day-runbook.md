# 阿里云上线当天操作顺序表

这份文档只解决一件事：

- 上线当天到底按什么顺序做，才最稳、最省事

建议按下面顺序执行，不要跳步。

## 1. 上线前 1 天

先完成这些准备：

1. 确认 ECS、域名、备案、证书申请条件都已准备好。
2. 确认 [docs/linux-deploy-commands.md](docs/linux-deploy-commands.md) 里的部署命令你已经看过一遍。
3. 确认 [docs/alicloud-checklist.md](docs/alicloud-checklist.md) 里的项目都没有明显缺口。
4. 准备好生产环境 `.env` 内容。
5. 准备好新的正式密码，不要继续使用默认密码。

## 2. 上线当天开始前

正式动手之前，先确认：

1. 当前本地代码已经是你要上线的版本。
2. `npm run lint` 已通过。
3. 如果你打算启用真实模型，LLM key 已准备好。
4. 你知道数据库文件和 uploads 目录要落在哪个持久化位置。

## 3. 服务器初始化

先做基础设施：

1. 登录 ECS。
2. 安装 Node.js、Nginx、PM2。
3. 创建应用目录、数据目录、备份目录。
4. 检查安全组是否已放行 22、80、443。

这一步做完前，不要急着上传项目代码。

## 4. 上传代码并安装依赖

顺序如下：

1. 上传项目代码到应用目录。
2. 执行 `npm install`。
3. 执行 `npx prisma generate`。
4. 创建生产 `.env`。

这一步完成后，先不要立即启动服务。

## 5. 先做持久化，再初始化数据库

这是当前最容易漏的一步。

顺序必须是：

1. 先创建 SQLite 持久化目录。
2. 先创建 uploads 持久化目录。
3. 再把 `prisma/dev.db` 和 `public/uploads` 接到持久化路径。
4. 然后再执行 `npm run db:push`。
5. 首次上线时再决定是否执行 `npm run db:seed`。

不要反过来做。否则很容易把数据先写进代码目录，后面再迁移时增加额外风险。

## 6. 构建并启动应用

顺序如下：

1. 执行 `npm run build`。
2. 用 PM2 启动应用。
3. 执行 `pm2 status` 检查状态。
4. 执行 `pm2 logs wsy-happy-everyday` 看是否有明显报错。
5. 本机用 `curl -I http://127.0.0.1:3000` 确认服务已起来。

## 7. 配置 Nginx 和 HTTPS

顺序如下：

1. 拷贝并修改 Nginx 配置。
2. 执行 `sudo nginx -t`。
3. 执行 `sudo systemctl reload nginx`。
4. 先确认 HTTP 可访问。
5. 再申请 HTTPS 证书。
6. 证书完成后，再次确认域名访问正常。

## 8. 上线后第一轮功能验收

不要一上来就全量测所有功能，先测最关键路径：

1. 打开登录页。
2. 用 `user1` 登录。
3. 确认首页能正常进入。
4. 发送一条文字消息。
5. 发送一张图片。
6. 检查猫圈是否新增。
7. 创建一条悄悄话。
8. 删除这条悄悄话。
9. 退出登录。

这 9 步走通，说明核心功能已经可用。

## 9. 上线后第二轮安全动作

第一轮功能确认后，立刻做这些：

1. 修改默认账号密码。
2. 再验证一次改密码后旧登录态失效。
3. 检查未登录访问首页是否会跳回登录页。
4. 检查未登录访问 API 是否返回 401。

## 10. 上线后第三轮持久化确认

这是当前阶段最关键的“别丢数据”检查：

1. 重启 PM2 进程一次，确认数据还在。
2. 如条件允许，重启服务器一次，确认数据和上传图片还在。
3. 检查 SQLite 文件是否确实位于数据目录。
4. 检查 uploads 是否确实位于持久化目录。

## 11. 上线当天备份

正式对外前，至少执行一次真实备份：

1. 备份 SQLite 文件。
2. 打包 uploads 目录。
3. 确认备份文件真的生成成功。

不要只写脚本，不实际执行。

## 12. 可以对外开放的判断标准

满足下面这些，再正式开放给自己长期使用：

1. 域名访问正常。
2. HTTPS 正常。
3. 登录正常。
4. 聊天正常。
5. 图片上传正常。
6. 悄悄话正常。
7. 改密后旧会话失效。
8. 数据持久化正常。
9. 备份已实际跑通过一次。

## 13. 上线当天不要做的事

为了避免把简单事情复杂化，当天不要临时做这些改动：

1. 不要临时改数据库类型。
2. 不要临时接对象存储。
3. 不要临时改部署架构。
4. 不要一边上线一边改产品功能。
5. 不要在当天引入新的依赖或大改 UI。

上线当天的原则只有一个：

- 用当前最稳定的版本，按最短路径把服务稳稳跑起来。
