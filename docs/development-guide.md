# 猫咪小家开发文档

## 1. 环境要求

- Node.js 22+
- npm 10+
- Windows PowerShell 可运行

## 2. 本地启动

```bash
npm install
npm run db:push
npm run db:seed
npm run dev
```

访问：

```text
http://127.0.0.1:3000
```

## 3. 默认账号

```text
user1 / cat123
user2 / cat123
```

说明：用户可以在个人资料里修改用户名、头像和简介；密码修改只在登录页完成。登录页会读取数据库中的最新用户列表，并对连续输错密码做基础节流。
默认账号现在由 [prisma/seed.ts](prisma/seed.ts) 按固定 id 维护：`user1 -> default-user-1`、`user2 -> default-user-2`。这样重复执行 seed 时不会因为用户名变动而额外生成新的默认账号。

## 4. 环境变量

复制 `.env.example` 为 `.env`，或直接编辑现有 `.env`。

```bash
DATABASE_URL="file:./dev.db"
APP_SESSION_SECRET="local-dev-secret-change-before-production"
LLM_BASE_URL="https://api.deepseek.com"
LLM_API_KEY=""
LLM_MODEL="deepseek-v4-pro"
```

说明：开发环境未配置 `APP_SESSION_SECRET` 时会使用本地默认值；生产环境现在会直接报错并拒绝启动。默认账号密码会在 seed 或首次成功登录后写入为哈希值。
上传限制：头像和聊天图片只接受 png、jpg、webp、gif，服务端会按文件头校验真实格式，不接受伪装扩展名或伪装 MIME 的文件。

DeepSeek 示例：

```bash
LLM_BASE_URL="https://api.deepseek.com"
LLM_API_KEY="你的 key"
LLM_MODEL="deepseek-v4-pro"
```

也支持使用 `DEEPSEEK_BASE_URL`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 这组变量名；未显式设置时，服务端会默认使用 DeepSeek 官方地址和 `deepseek-v4-pro`。

## 5. 常用命令

```bash
npm run dev      # 开发服务
npm run build    # 生产构建
npm run start    # 启动生产服务
npm run lint     # TypeScript 类型检查
npm run db:push  # 初始化/同步 SQLite 表
npm run db:seed  # 写入默认用户和猫咪
npm run db:reset # 重置数据库并重新 seed
```

## 6. 开发工作流

### 修改 UI

主要文件：

```text
components/chat-app.tsx
app/globals.css
tailwind.config.ts
```

改完后执行：

```bash
npm run lint
npm run build
```

如果开发服务已运行，Windows 上 `npm run build` 可能因为 Prisma DLL 被占用而失败。先停止 dev server 后再 build。

### 修改 API

主要目录：

```text
app/api/
lib/
prisma/
```

修改 API 后至少验证：
- 未登录返回 401。
- 登录后正常返回。
- 错误输入有明确错误信息。
- 数据写入后刷新页面仍正确。
- 高频写接口达到阈值时应返回 429，并带明确提示文案。

### 修改数据库

当前本地初始化由 `prisma/init-db.ts` 负责。

如果修改 `prisma/schema.prisma`，需要同步修改：

```text
prisma/init-db.ts
prisma/seed.ts
```

然后执行：

```bash
npm run db:reset
```

## 7. 功能测试清单

### 登录

- `user1` 可登录。
- `user2` 可登录。
- 未登录访问首页会跳转登录页。
- 登录页显示数据库中的最新用户名称和头像。
- 同一来源对同一用户名连续输错 5 次后，第 6 次会返回限流错误；等待约 10 分钟后恢复。
- 当前节流状态会持久化到数据库里的 `AppSetting`，因此重启开发服务后锁定不会立即消失。

### 猫咪列表

- 默认 5 只猫展示正常。
- 选择猫咪后右侧聊天对象切换正常。

### 创建猫咪

- 点加号只打开创建弹窗，不立即创建。
- 取消创建后列表不增加猫咪。
- 创建时可填写头像、名字、性格、语气、背景故事，以及当前用户自己的称呼和互动偏好。
- 创建成功后直接回到聊天界面并选中新猫。
- 重名时提示换名。

### 编辑猫咪

- 设置抽屉可以修改猫咪资料。
- 上传头像后刷新仍显示。
- 当前用户只能修改自己的称呼和互动偏好。
- 修改称呼或互动偏好后，后续聊天优先使用新的用户专属上下文。
- 关系卡里能看到当前用户自己的专属记忆和关系状态。

### 个人资料

- 个人资料弹窗可以修改用户名、显示名称、头像和个人简介。
- 修改后的用户信息会同步显示在首页侧边栏和登录页。

### 修改密码

- 修改密码入口位于登录页。
- 需要先选择用户，再填写当前密码、新密码和确认新密码。
- 修改成功后可直接用新密码登录。
- 修改密码后，旧登录态应立即失效，需要重新登录。
- 个人资料弹窗不再承担改密码职责。

### 删除猫咪

- 删除入口位于危险操作区。
- 输入错误名称不能删除。
- 输入正确名称才能删除。
- 输入前后空格不影响确认。
- 删除后列表移除该猫。
- 删除后相关消息、记忆、称呼被级联清理。
- 不能删除到一只猫都不剩。

### 聊天

- 用户消息能保存。
- 用户可给猫咪发送图片。
- 猫咪回复能保存。
- 用户 1 发的消息，用户 2 可见。
- 未配置 LLM 时返回备用回复。
- 配置 LLM 后调用真实模型。
- 同一用户 1 分钟内连续发送超过 12 次消息或图片时，应返回 429 提示稍后再试。

### 猫咪猫圈 / 电子相册

- 给猫咪发送图片后，会生成一条用户图片消息和一条猫咪回复。
- 同一张图片会自动进入该猫咪的猫圈列表。
- 猫圈卡片应显示图片、猫咪文案和时间。

### 悄悄话留言卡

- 可以正常创建、送达、查看和删除悄悄话。
- 同一用户 10 分钟内连续创建超过 6 张悄悄话时，应返回 429 提示稍后再试。
- 删除单条猫圈时，对应上传图片文件也应一并清理。
- 删除猫咪时，相关猫圈图片会一起清理。

## 8. 代码约定

- TypeScript 开启 `strict`。
- 手写 UI 优先保持苹果风、淡色、紧凑。
- 图标使用 `lucide-react`。
- 危险操作必须二次确认。
- 不把 API key 暴露到前端。
- 新增持久化字段时同时更新文档和 seed。

## 9. 已知注意事项

- 当前密码已改为哈希存储；旧明文数据会在成功登录后自动迁移。
- 当前 SQLite 适合本地开发，不适合多人高并发生产。
- 当前头像上传在本地磁盘，云部署时需要对象存储。
- 当前共享记忆和用户专属记忆都还是简单摘要追加，不是智能总结。
- 当前没有自动化测试框架，依赖手动/API 冒烟测试。

## 10. 上线前检查清单

### 环境与部署

- 确认生产环境已设置 `APP_SESSION_SECRET`，且为独立随机长字符串。
- 确认生产环境已设置 `DATABASE_URL`，并验证数据库文件或挂载卷具备可写权限。
- 如果需要真实模型回复，确认 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 都已配置。
- 如果部署环境会重建容器或覆盖工作目录，确认 `public/uploads/` 已迁移到持久化存储或对象存储。
- 在目标部署环境执行一次 `npm run build`，不要只在本地开发机验证。

### 账号与安全

- 使用 `user1`、`user2` 各登录一次，确认登录、退出登录、首页鉴权跳转都正常。
- 连续输错密码 6 次，确认第 6 次返回限流提示；等待窗口过去后可恢复登录。
- 修改任一账号密码后，确认旧登录态立即失效，刷新页面会回到登录页。
- 确认未登录直接访问 API 时会返回 401，而不是 200 或空数据。

### 关键功能

- 发送纯文本消息，确认用户消息、猫咪回复、刷新后历史记录都正常。
- 发送图片消息，确认图片写入成功、猫咪回复成功、对应内容进入猫圈。
- 删除单条猫圈，确认界面移除且对应上传图片文件被清理。
- 上传并替换用户头像、猫头像，确认刷新后仍显示，且旧上传文件不会残留引用。
- 创建、送达、回复、删除悄悄话各走一遍，确认双方视角都符合当前规则。

### 限流与异常

- 同一用户 1 分钟内连续发送超过 12 次消息或图片，确认接口返回 429。
- 同一用户 10 分钟内连续创建超过 6 张悄悄话，确认接口返回 429。
- 在未配置 LLM 的环境下发送消息，确认会回退到本地备用回复而不是报 500。
- 手动删除或失效 `cat_session` 后刷新页面，确认前端能正常回到登录页。
