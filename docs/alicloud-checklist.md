# 阿里云部署最终 Checklist

这份清单只服务一个目标：

- 用阿里云把当前项目低成本、低复杂度上线

如果你需要按时间顺序执行，可以继续看 [docs/alicloud-launch-day-runbook.md](docs/alicloud-launch-day-runbook.md)。

适用前提：

- 当前仍采用单台 ECS
- 当前仍使用 SQLite
- 当前仍使用本地持久化 uploads
- 当前用户规模仍然很小，以两位固定用户为主

## 1. 阿里云资源准备

上线前确认：

- 已购买 ECS，建议 Ubuntu 22.04。
- 规格至少 2 核 2G，系统盘至少 40G SSD。
- ECS 已分配公网 IP。
- 如果使用域名，中国大陆地域已准备备案。
- 如果还没有备案，先用 IP 做内部试用，不要正式开放域名。

## 2. 安全组与网络

安全组至少确认：

- 22 端口已放行，用于 SSH。
- 80 端口已放行，用于 HTTP 与证书签发。
- 443 端口已放行，用于 HTTPS。
- 没有把 3000 端口直接暴露到公网。

如果使用阿里云防火墙或其他网络策略，也要同步检查一次。

## 3. 域名与证书

如果要正式上线域名：

- 域名已解析到 ECS 公网 IP。
- 域名备案状态已满足访问要求。
- Nginx 已反代到 `127.0.0.1:3000`。
- HTTPS 证书已签发成功。
- 访问域名时，浏览器不会出现证书告警。

## 4. 运行环境

服务器上至少确认：

- Node.js 22+ 已安装。
- npm 可用。
- PM2 可用。
- Nginx 可用。
- 应用目录、数据目录、备份目录都已创建。

## 5. 数据持久化

这是当前阿里云上线里最不能漏的一项。

必须确认：

- SQLite 数据文件不在会随发布覆盖的代码目录里。
- `public/uploads/` 已单独持久化。
- 代码目录可以重发，但数据库和上传目录不会跟着丢失。

如果你用的是云盘挂载或本机数据目录，重点是路径要稳定、重启后仍然存在。

## 6. 环境变量

上线前必须确认：

- `APP_SESSION_SECRET` 已设置为独立随机长字符串。
- `DATABASE_URL` 已正确指向生产使用的 SQLite 文件。
- 如果启用真实模型，`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 都已设置。
- `.env` 文件不会被提交到公开仓库。

## 7. 应用启动

上线前确认：

- 已用 PM2 启动应用。
- `pm2 status` 显示应用在线。
- 应用监听在本机 3000 端口。
- 服务器重启后，PM2 能自动拉起应用。

## 8. 构建与初始化

至少完成过一次：

- `npm install`
- `npx prisma generate`
- `npm run db:push`
- `npm run build`

如果是首次上线，再确认是否执行：

- `npm run db:seed`

如果不是首次上线，不要机械重复 seed。

## 9. 上线前功能验证

至少逐项确认：

- `user1` 能登录。
- `user2` 能登录。
- 退出登录正常。
- 未登录访问首页会回到登录页。
- 修改密码后旧会话立即失效。
- 文本聊天正常。
- 图片上传正常。
- 猫圈显示正常。
- 删除猫圈后对应图片会一起清理。
- 用户头像和猫头像替换后刷新正常。
- 悄悄话可创建、查看、删除。
- 高频发消息会返回 429。
- 高频创建悄悄话会返回 429。
- 未配置 LLM 时会走备用回复，不会报 500。

## 10. 上线当天安全动作

正式上线前至少做完：

- 修改默认账号密码。
- 确认默认密码不再继续使用。
- 核对 `APP_SESSION_SECRET` 不是开发默认值。
- 确认 Node 进程不直接暴露公网。
- 确认只有 80/443 对外提供服务。

## 11. 日志与排障

至少确认你知道这些命令怎么用：

- `pm2 status`
- `pm2 logs wsy-happy-everyday`
- `sudo nginx -t`
- `sudo systemctl reload nginx`

上线初期如果出问题，先看：

- PM2 日志
- Nginx 配置
- `.env` 是否完整
- 数据目录和 uploads 目录是否真实存在

## 12. 备份

当前阶段最低要求：

- 每天备份 SQLite 文件一次。
- 每天打包 uploads 目录一次。
- 备份文件至少保留最近 7 天。

如果条件允许，再加一层：

- 把备份同步到 OSS 或另一块盘。

## 13. 当前阶段不必做的事

为了控制成本和复杂度，当前阶段不建议优先做：

- 不急着上 RDS。
- 不急着上 OSS。
- 不急着 Docker 化。
- 不急着做 CI/CD。
- 不急着做多机部署。

当前最划算的目标只有一个：

- 先在阿里云上稳定跑起来，并且数据不丢。

## 14. 最终上线判断

满足下面条件，就可以上线试用：

- ECS 已可通过域名或 IP 访问。
- HTTPS 正常。
- PM2 正常。
- Nginx 正常。
- SQLite 持久化正常。
- uploads 持久化正常。
- 默认密码已修改。
- 上线前功能清单已过完。
- 备份方案已实际执行过一次。

到这一步，就已经达到当前项目最合适的上线标准了。
